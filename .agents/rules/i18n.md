# i18n and Built-in Copy

## Ownership

- VelvetUi owns all generic reusable copy (button labels, empty states, validation fallbacks, aria descriptions)
- Do not leave hardcoded user-facing strings in component logic; add them to `src/i18n/messages.ts`
- Do not reflexively expose every label as a required prop; the library should own sensible defaults

## Text Resolution Order

1. Semantic prop override — when customization is part of the genuine public API (e.g. `label`, `message`)
2. `messages` override — when consumer-level localization is needed
3. Built-in `useI18n()` default — the library fallback for generic copy

## Adding New Copy

- Add the key to `src/i18n/messages.ts`
- Consume via `useI18n()` in the component
- Only expose as a prop when customization is a real consumer requirement, not as a reflex

## What Belongs Here vs Props

- Generic labels ("Close", "Loading…", "No results", validation fallbacks) → `messages.ts`
- Domain-driven or semantic text that varies per usage → explicit `label`/`message` prop
- Do not push generic copy to props with the intention of letting consumers always override it
