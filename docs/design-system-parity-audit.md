# Ponowny audyt zgodności z design systemem

Przegląd całej referencji `velvet`, obejmujący 12 grup biblioteki oraz fundamenty, z wyłączeniem templates i komponentów należących do VelveData: DataGrid, ColumnManager, VirtualList, VirtualTable, QueryBuilder i ich kontraktów. Wszystkie 16 wykrytych braków zostało następnie poprawionych w źródłach na zlecenie użytkownika. Przegląd zmian pozostał statyczny; nie potwierdza działania w przeglądarce ani przejścia kompilacji.

Inwentaryzacja referencji zawiera 183 pliki wejściowe deklaracji: 178 w zakresie i 5 wyłączonych. Wcześniejsze mapowanie 578 nazw eksportowanych wskazuje 554 nazwy dostępne w bibliotece i 24 należące do VelveData. Nie znaleziono brakującej całej rodziny komponentów. Obecność eksportu nie dowodzi jednak zgodności jego zachowania — poniżej są pominięcia wewnątrz istniejących komponentów.

### Usunięcie globalnych animacji legacy

Z `src/styles/tokens/base.css` usunięto komentarz o zgodności plain HTML, sześć starych globalnych keyframes (`vui-fade-in`, `vui-rise-in`, `vui-sheet-in`, `vui-spin`, `vui-pulse`, `vui-pop-in`) oraz klasę `.vui-pop-in` i jej regułę reduced-motion. Wyszukiwanie w źródłach biblioteki nie wykazało konsumentów tych nazw poza usuniętą klasą. Animacje komponentów są definiowane w CSS Modules właściciela lub współdzielonym module animacji.

To celowa zmiana kompatybilności zaakceptowana przez użytkownika. Konsument plain HTML, który używał tych globalnych nazw lub klasy, musi dostarczyć własną animację albo używać komponentu biblioteki z jego obsługiwanym zachowaniem. Nazwy generowane przez CSS Modules nie są publicznym zamiennikiem tych aliasów. Referencja velvet i wygenerowany dist nie zostały zmienione w ramach tej poprawki.

Zmiana typowania Handle może wymagać rozszerzenia typu callbacka ref/zdarzenia z HTMLButtonElement do HTMLElement, jeżeli konsument deklarował go jawnie. Uchwyt przyciskowy nadal renderuje natywny button.

## Różnice odrzucone jako braki

- Table.addRow jest świadomym slotem na natywny wiersz, z TableAddRowAction jako odpowiednikiem referencyjnej akcji. Historia dodaje slot i komponent razem oraz później dopasowuje ich prezentację. Nie jest to brak funkcji dodawania.
- Pozycyjne przenoszenie TreeView jest dostępne przez onMovePosition; starsze onMove zachowuje dwuargumentową integrację. Historia dodaje onMovePosition jako rozszerzenie bez zrywania starszego kontraktu. Nie brakuje algorytmu przenoszenia przed/za/do węzła.
- Ogólne, zlokalizowane komunikaty zamiast surowych error.message są wymagane przez `.agents/rules/security-boundaries.md`. Nie są utratą przypadkowo pominiętego tekstu.
- Brak fallbacku kopiowania przez document.execCommand odpowiada regule dotyczącej przestarzałych API. Nie proponuje się jego przywracania w ramach zgodności.
- Wyczyszczenie starych wyników wyszukiwania asynchronicznego podczas nowego zapytania nie zostało uznane za potwierdzony brak. Kod celowo rozdziela najnowsze zapytanie od nieaktualnych opcji.
- CSS Modules, rozdzielenie plików, prymitywy typograficzne, lokalizacja, wspólny stos warstw i integracja AuthButton z providerem pozostają przyjętymi adaptacjami. Sama zmiana nazwy klasy lub folderu nie jest ustaleniem audytu.
- Wcześniejsze poprawki loaderów, animacji i widoczności zakotwiczonych paneli są już obecne. Nie są ponownie liczone jako pozostałe braki. Przejrzano warianty loaderów, w tym liczbę elementów i lokalne/wspólne keyframes; nie potwierdzono kolejnego pominięcia w tej części.
- Znane ograniczenie fallbacku pozycjonowania bez natywnego Popover API było już opisane. Nie jest nowym pominięciem referencji.

## Zakres dowodów i ograniczenia

Przegląd obejmuje actions, charts, data, display, feedback, forms, layout, media, menus, navigation, patterns i primitives. Sprawdzano deklaracje, główne źródła, powiązane helpery i współdzielone moduły CSS; przy niejasnej różnicy również historię zmiany. Wcześniejsza inwentaryzacja obejmuje 560 referencyjnych/bibliotecznych interfejsów Props, 174 referencyjne style komponentów, 15 plików tokenów i 8 fontów. Te liczby opisują pokrycie inwentaryzacji, nie dowodzą równoważności każdego typu, selektora lub przebiegu interakcji.

Lista dokumentuje naprawione luki z konkretną ścieżką przyczyna–skutek, a nie wszystkie tekstowe różnice między React a Solid. Nie stanowi gwarancji braku dalszych usterek. Po edycjach ponownie odczytano zmienione źródła i przejrzano różnice, w tym kolejność/specyficzność CSS, cykl życia obrazu, przepływ wartości 0 i usuwanie elementu pomiarowego. Nie porównywano wizualnie renderów ani wszystkich kombinacji stanów, nie uruchomiono aplikacji, kompilacji, narzędzi analitycznych lub testów. `npm run verify` pozostaje nieuruchomione zgodnie z decyzją użytkownika. Templates i showcase z templates pozostają poza zakresem.
