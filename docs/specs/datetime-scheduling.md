# Date, Time And Scheduling

Status: Approved/Frozen. Source input/object shapes are evidence and may be redesigned. Current values are local date/time strings, not timestamps, except where explicitly stated; the approved local serialization format and calendar outcomes remain fixed.

## Date And Time Values

- `SOURCE-DATE-001`: Date picker values use `YYYY-MM-DD`; date-time value uses `YYYY-MM-DDTHH:mm`. Empty date-time is empty string; date with no time serializes as `T00:00`. DatePicker/DateTimePicker/TimePicker expose optional values but no internal selection state: consumers must update props from onChange for committed value to remain visible. Preserve this representation and avoid implicit timezone conversion for date-only selection.
- `SOURCE-DATE-002`: Calendar is Monday-first and displays a fixed six-week/42-cell grid including adjacent-month days. Month labels use provided locale or runtime locale. Today is local date. Prev/next month navigation updates view; selection is constrained by optional inclusive min/max ISO strings.
- `SOURCE-DATE-003`: `DatePickerProps` extends ARIA field props; optional value, locale, disabled, min/max/size; required onChange(string). Trigger label is value or localized YYYY-MM-DD placeholder. Opens non-modal dialog anchored to field; selected value determines initial viewed month; selecting valid date emits ISO and closes. Close outside/Escape leaves value unchanged. It marks today/selected days and disables dates lexically outside inclusive bounds.
- `SOURCE-DATE-004`: `DateRange` is `{start:string,end:string}`. `DateRangePickerProps` requires value/onChange and accepts id/locale/size/disabled/min/max/ARIA field props. Start/end triggers share one popup; active field determines selected endpoint. Selecting a start while current end >= new start emits `{start:new,end:currentEnd}` and closes; otherwise emits `{start:new,end:''}`, holds popup and switches active field to end. Selecting an end uses current value start or pending start; if no start, emits it as pending start; otherwise emits chronologically ordered complete range and closes. Closing cancels pending start. Range highlight includes endpoints; min/max disable selection.
- `SOURCE-DATE-005`: `TimePickerProps` extends ARIA field props; optional value/disabled/step/size, required onChange. Step defaults 30; finite positive step is floored with minimum 1, invalid uses 30. Builds values from 00:00 up to but excluding 24:00. Trigger uses localized HH:MM placeholder. Opens listbox anchored right; scrolls selected option into view; selection emits string and closes. Source does not wire keyboard opening/focus navigation beyond native option buttons; replacement follows the approved keyboard/focus behavior in `USER-DEC-011`.
- `SOURCE-DATE-006`: `DateTimePickerProps` accepts optional id/value, required onChange, disabled/locale/minDate/maxDate/step/size and ARIA field props. It composes DatePicker and TimePicker; date changes preserve current time; time changes with no date emit empty string. Time control disabled until date exists. `joinDateTimeValue(date, time)` returns empty if no date, otherwise `${date}T${time||'00:00'}`. `splitDateTimeValue` returns the first two `T`-separated pieces and discards any later pieces; this is accidental-looking behavior requiring compatibility classification.
- `SOURCE-DATE-007`: Date utility outputs are local-calendar based. Grid has exactly 42 cells; malformed month parsing falls back to current month, malformed date parts fall back to today but do not validate impossible numeric day/month combinations. `isoToDate` uses local Date constructor; source add-days and day-difference use local dates and millisecond/24h rounding. Date inputs are compared as strings. `USER-DEC-003` fixes the public model as local date/time strings without timezone conversion; replacement calendar-day arithmetic must avoid DST-sensitive elapsed-millisecond differences.

## Calendar And External Calendar

- `SOURCE-DATE-010`: `CalendarHeaderProps` requires monthLabel/onPrevious/onNext, optional titleContent. `DateTimeFieldTriggerProps` extends div-native props; optional open, required `trigger(triggerClass)=>JSX`, optional children. Open adds classes to wrapper and passed trigger class. `CalendarGrid` is an internal reusable part: weekday labels, day cells, class/disabled/aria-label/content/filter, button type/pressed callback, double-click and drag-over/drop/leave callbacks are caller-supplied. Date cells render in caller order.
- `SOURCE-DATE-011`: Calendar-event data contains a title, nullable local start, optional duration/details/location and synced state. Missing start disables the unsynced action. The generated Google Calendar URL percent-encodes title/details/location; `dates` contains compact UTC start/end values and defaults duration to 60 minutes. A supplied open callback receives the URL instead of opening a new tab with `noopener,noreferrer`. Synced state displays a status icon instead of the action. Invalid timestamps and non-finite/negative durations follow `AGENT-DEC-025`; valid local values convert to UTC at the integration boundary.

## Scheduler

- `SOURCE-SCHED-001`: `SchedulerEvent` is `{id,title,date,endDate?,time?,description?}`. `SchedulerProps` extends div-native props excluding onChange; requires events; optional onEventsChange, selectedDate/defaultSelectedDate/onSelectedDateChange/onMonthChange/locale/draggableEvents/dayNames. Initial date defaults local today; selected date is controlled when supplied, otherwise internal. Editable create/edit/delete and drag affordances exist only when onEventsChange supplied. Dragging defaults enabled unless `draggableEvents=false`. Month callback receives first day of month in `YYYY-MM` format.
- `SOURCE-SCHED-002`: Calendar view initializes to current month, shows adjacent days, event count per date and selected/today/drag-over states. Supplying defaultSelectedDate changes selected date but does not initialize displayed month away from current month; source does not run the month-sync effect initially. Prev/next update month; Today updates view and selection. Selecting date updates selection; double-click opens creation when editable.
- `SOURCE-SCHED-003`: Creation requires nonempty trimmed title, stores selected date/time/description (empty optional fields omitted), generates ID, appends event, closes/resets. Edit preserves event ID and shifts endDate by same date offset, saves trimmed title/description and optional time. Delete requires confirmation. Escape cancels create/edit; focus goes to title input on open.
- `SOURCE-SCHED-004`: Multi-day events appear on every inclusive date between start/end even if input endpoints reversed. Drag move preserves span length; resize-end cannot precede start and omits endDate when same as start. Drag is available only when `draggableEvents !== false` and onEventsChange exists; callbacks receive replacement array. Same-date move and unknown event produce copied array/no effective change.
- `SOURCE-SCHED-005`: Event display date, create/edit form, empty-day state, no-edit read-only mode, and localized labels are preserved. Current forms include date/time and optional description, but event `endDate` is not directly editable through form.
- `AGENT-SCHED-006`: Replace mouse-only drag dependence with keyboard-operable move/resize actions that preserve event data meaning; one-day action semantics are defined by `AGENT-DEC-032`.
- `USER-DEC-011`: Calendar/date/time controls implement a roving-focus grid: Left/Right move one day, Up/Down one week, Home/End start/end of week, PageUp/PageDown previous/next month, Enter/Space selects; Escape closes popup and returns focus to trigger. DateRangePicker keeps the active start/end field when navigating. Disabled dates are skipped and active descendant/focus never references a removed cell.
- `USER-DEC-003`: All date/time picker and scheduler strings remain local calendar values without timezone conversion. Calendar integration converts a local event start at the external boundary, then serializes the resulting instant in the provider-required UTC format.

## Acceptance

- Calendar day selection, range completion/reordering, time generation, date serialization, inclusive multi-day display, create/edit/delete, and move/resize transformations match source-backed requirements.
- Test under multiple local time zones and DST transitions; date-only values remain local calendar dates, while UTC conversion is limited to external integrations per `USER-DEC-003`.
- `coverage.md` maps all calendar, scheduler and date/time-picker capabilities/settings to behavior and acceptance evidence before approval; source type/prop names are not required.
