# Overlays And Feedback

Status: Draft. Preserve externally visible lifecycle, action ordering and outcomes while replacing fragile focus/portal mechanics where necessary. Source prop/object shapes and callback names are descriptive evidence; the replacement API may differ.

## Overlay Contracts

- `SOURCE-OVERLAY-001`: Classify each layer as modal, non-modal, or transient; accessible name/description, focus entry/containment/return, Escape, outside interaction, nesting, scroll locking, and reduced motion are observable contracts. Clean all listeners/observers/timers and restore global state on close/unmount.
- `SOURCE-OVERLAY-002`: `Dialog` requires controlled open/onClose/children; also accepts Props base and `aria-labelledby`/`aria-describedby`. It uses native `<dialog>.showModal()`, portals, closes on cancel/Escape and backdrop click; focus trap restores focus. It generates title ID and supplies it through context. `DialogTitle` requires label, renders h3/titleLg using dialog context title ID; outside Dialog it has no generated title association. `DialogBody` and `DialogActions` require JSX children, accept class/Props base, and render styling wrappers.
- `SOURCE-OVERLAY-003`: `Sheet` requires open/onClose; optional label/subtitle/children/actions, side bottom/left/right default bottom, size sm/md/lg default md. Modal dialog with close icon; backdrop/Escape dismiss; focus trap and entry transition. Caller ARIA label/description IDs are joined with generated IDs when text is present.
- `SOURCE-OVERLAY-004`: `ConfirmDialog` requires open/label/message/confirmLabel/onConfirm/onClose; optional variant primary/danger default primary. Cancel closes via onClose; confirm invokes onConfirm but does not directly call onClose. `ConfirmAction` requires label/message/confirmLabel/onConfirm/children render function; optional variant/onClose. Render context supplies openConfirm/closeConfirm/isConfirmOpen accessor. Cancel/close invokes optional onClose. Source closes after awaited callback even when rejected; `AGENT-DEC-005` supersedes that failure transition: on rejection keep confirmation open, show localized non-sensitive error, clear pending state and allow retry; on success close.
- `SOURCE-OVERLAY-005`: `Popover` requires trigger render function and content string; optional position top/bottom/left/right default bottom, controlled open, onOpenChange. Trigger renderer receives onClick toggle. Outside/Escape close; content is non-modal dialog anchored to wrapper with 8px offset and arrow. When open prop is controlled, internal toggle still updates but rendered state follows prop; callback reports attempted state.
- `SOURCE-OVERLAY-006`: `Tooltip` extends div-native props, requires content string; optional position top/bottom/left/right default top. It reveals 200ms after pointer enter/focus, hides on pointer leave/blur, sets aria-describedby only while visible, portals/floats with 8px offset and arrow. Timer is cleared on disposal.
- `SOURCE-OVERLAY-007`: `FloatingProps` extends div-native props and requires anchor accessor (HTMLElement or virtual reference) and open boolean. Optional placement bottom-start, offset 0, padding 8, matchWidth false, exposeAvailableSize false, animationFrame false, extraMiddleware[], ref/style/children. It portals to body when open, fixed positions by translate3d, applies offset/flip/shift/size then optional matchWidth and additional middleware, publishes data-placement and arrow/available-space custom properties. Updates on ancestor scroll/resize and ResizeObserver; animationFrame mode checks anchor geometry each frame. This public behavior must be preserved, not the source private algorithm.
- `SOURCE-OVERLAY-008`: `ContextMenu` requires children and items, where each item is separator or `{label,icon?,onClick,danger?,disabled?}`. Right-click prevents native menu and opens at pointer location using a virtual anchor. First enabled item receives focus. Arrows wrap, Home/End endpoints, Escape closes; outside closes. Selecting enabled item closes before invoking callback.
- `SOURCE-OVERLAY-009`: `TourStep` is `{target,title,content,placement?:top|bottom|left|right}`. `Tour` requires steps/open/onClose, optional onComplete. Open resolves `document.querySelector(target)`; spotlight follows target across captured scroll/resize, floating card uses mapped start placement/arrow. Next/back, skip/Escape; last Next calls onComplete then onClose. Closing resets step to zero. No dialog semantics/focus trap are present in source. Missing target leaves overlay rendered but floating card absent; `AGENT-DEC-015` requires accessible recovery without stranded focus/background state.
- `SOURCE-OVERLAY-010`: `LightboxImage` is `{src,alt?,caption?}`. `Lightbox` requires images/open/onClose, optional startIndex. It is visible only if open and images nonempty, clamps start index when it changes, clamps current index if list shrinks; prev/next/left-right arrows wrap. Backdrop pointer-down, close button, Escape close. Modal dialog has localized viewer name, image alt defaults empty, optional caption/counter. It reference-counts nested instances to lock/restore body overflow.

## Feedback And Async Status

- `SOURCE-FEEDBACK-001`: `Toast` public functions add/remove/clear notifications, mark one/all read and expose reactive collections/hooks. Adding creates unique ID, adds transient toast and unread timestamped notification; default duration 3000ms, duration <=0 persists until removed. Toast removal does not remove notification. Provider cleanup clears timers and both collections. Error toast uses alert role; other toast status; viewport has polite live region and close control.
- `SOURCE-FEEDBACK-002`: `NotificationCenter` lists newest-first notifications, optional maxItems truncates display, unread count, mark read/all, remove one, clear all, localized empty state and time display. Actions mutate shared toast notification store.
- `SOURCE-FEEDBACK-003`: `ToastMessage` is `{id,type,message,duration?}`, with type success/error/info/warning. `ToastNotification` adds `createdAt` epoch milliseconds and `read`. `addToast({type,message,duration?})` returns ID, adds newest notification at front and toast at end, then schedules dismissal for positive duration. `removeToast` leaves notification intact; notification removal/clear does not dismiss toast. Provider disposal clears all timers, toast records and notifications. `ToastViewport` portals to body, uses polite region/non-atomic announcements, error alert role versus other status roles, localized close control, and per-toast duration progress.
- `SOURCE-FEEDBACK-004`: `NotificationCenter` extends div-native props except onChange; accepts optional label and maxItems. `maxItems <=0` or absent shows all notifications; otherwise slices newest-first list. It exposes region role by default, localized name, polite live region, time-only locale formatting, unread count, mark all read, clear all, mark one read, and dismiss one. Empty state appears if no displayed items.
- `SOURCE-FEEDBACK-005`: `Alert` extends div-native props; required variant `info | success | warning | error | danger | tip`, required message, optional label/icon/onClose; defaults icon by variant and role alert unless caller provides role. `danger` uses error visuals. `Banner` extends div-native props; optional variant info/success/warning/error/primary defaults primary, required message, optional action/onClose; role status unless caller provides role.
- `SOURCE-FEEDBACK-006`: `Badge` requires children; optional content string/number, variant primary/primarySoft/info/success/warning/error, max, dot and inline. Numeric content greater than max renders `max+`; dot suppresses text content. `Chip` requires label; optional variant info/warning/success/error/primary/primaryOutline/subtle, size sm/md, selected/filled/custom color, end adornment and click callback. It renders a span without click handler and a button with click handler. Custom color uses computed contrast text when filled/selected. `ClosableChip` requires label and onRemove, optionally disabled, and uses a separately named remove button.
- `SOURCE-FEEDBACK-007`: `EmptyState` accepts icon/message/label/hint/action and renders `message || label`; `InlineEmptyState` requires message and accepts action. `FallbackState` requires label/description, optional icon/action. `ErrorFallback` requires label/description/onRetry. `ErrorMessage` requires message and exposes alert role. `AccessDenied` requires label/description/goHomeLabel, optional onGoHome; without callback it navigates to `/`. `NotFound` only accepts optional onGoHome and uses localized copy; without callback it navigates to `/`.
- `SOURCE-FEEDBACK-008`: `Page` extends `AuthGuardProps`; without roles it renders children directly, with roles it wraps them in AuthGuard. `Kbd` forwards its supported HTMLElement native props/children. `SelectableChips` contract is specified in composite-widgets.
- `SOURCE-FEEDBACK-009`: `Progress` accepts optional value, variant primary/info/success/warning/error, size sm/md/lg, label, showValue; defaults primary/md. Undefined value is indeterminate; defined value clamps to 0..100 and optionally shows percent. `CircularProgress` accepts value, size, variant primary/success/warning/error, thickness default 4, showValue, label; size dimensions are 32/48/64 for sm/md/lg, and role progressbar carries label/value when determinate. `ScoreRing` is a meter clamped 0..100 and maps thresholds <51 error, 51..70 warning, 71..85 primary, >=86 success.
- `SOURCE-FEEDBACK-010`: `Skeleton` extends div-native props; defaults text variant and wave animation, supports circular/rectangular and pulse/wave/none, width/height as CSS length or number (number becomes px).
- `SOURCE-FEEDBACK-011`: `Countdown` accepts a duration, optional completion action, auto-start, format and size; defaults auto-start true, format mm:ss, size md. Formats hh:mm:ss/mm:ss/ss, resets when duration/auto-start changes, updates once per second, marks positive values under 10 seconds urgent, stops at zero and calls completion. Source timing is interval-based; duration validation, hidden-document catch-up and one-time completion follow the proposal in `AGENT-DEC-028`.
- `SOURCE-FEEDBACK-012`: `DualFilterBar` takes filter/sort option arrays `{value,label}`, active filter/sort strings, and separate change callbacks; renders two labeled toolbar groups. `ColorLabelSelectionDialog` and `ColorLabelManagerDialog` contracts are in domain-composites.
- `SOURCE-FEEDBACK-013`: Feedback messages/status/errors must remain perceivable without color alone; async states expose recovery and prevent duplicate submission where the source does so.
- `SOURCE-LOADER-001`: Source loaders share optional accessible label and optional custom loading message, with precedence explicit label > custom message > localized default. Unless explicitly `aria-hidden="true"`, loader defaults to `role="status"` and accessible label; hidden loader preserves caller-supplied role/label instead. Spinner defaults size lg. PageLoader defaults full-screen and exposes busy/live status unless hidden. Other loader-specific geometry is visual detail; replacement symbols and props may differ, but visual loading affordance and accessible status remain.
- `SOURCE-LOADER-002`: Public loaders include `BikeLoader`, `BouncingDotsLoader`, `ConcentricPulseLoader`, `CornerPulseLoader`, `DualPlaneSpinner`, `EllipsisLoader`, `EqualizerLoader`, `HoneycombLoader`, `JellyTriangleLoader`, `OrbitSquaresLoader`, `PageLoader`, `PulseRingLoader`, `RippleDotsLoader`, `ShapeTrailLoader`, `ShuffleGridLoader`, and `Spinner`. `ShapeTrailLoader` supports `circle | triangle | square`, default circle. Each export has its own translation key/messages type.

## Acceptance

- Keyboard-only open/close, initial/contained/returned focus, nested layers, backdrop, outside dismissal, escape, reduced motion, global scroll restoration, and screen reader names are correct.
- Async submit pending/close/failure transitions follow `AGENT-DEC-005`: no duplicate submission; failure leaves the workflow open with a non-sensitive retryable message; success follows its existing close/reset contract. Failure state is announced accessibly.
- Timers/listeners are cleaned up on unmount and tests validate overlapping toast/lightbox/provider lifetimes.
